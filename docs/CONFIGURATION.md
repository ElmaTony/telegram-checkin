# 配置与结果判定

本文面向需要编辑 YAML、调整成功词或排查会话定位问题的使用者。首次使用请先阅读 [README](../README.md)。

## 工作台分类

已有配置会自动参与分类，无需重新添加会话或修改签到动作。

| 维度 | 选项与含义 |
| --- | --- |
| 会话类型 | 群组／频道、论坛话题、私聊／机器人、类型待识别；不根据群名猜测细分类型 |
| 签到方式 | 文字、口令、口令＋按钮、图片＋文字、仅图片；多步会话按每一个所含方式参与筛选 |
| 动作结构 | 单步或多步，和签到方式独立；图文动作可以是多步中的第二步 |
| 共用系统 | 独立会话、已加入系统，或具体系统名称 |

这些条件可与账号、关键词和结果状态组合使用。选项数量会根据其他条件计算；多步会话可能计入多个方式，因此各方式数量之和可能大于会话总数。
统计卡片按所选账号计算，分类筛选不会自动改变发送范围。未解析的 `@用户名` 保留“类型待识别”；已有可靠发送目标时可据其确定类型。

## 发送与结果的边界

### 目标核验

导航有总超时。URL hash 只负责导航，**不能证明当前会话正确**。
必须核对可见聊天顶栏和输入框的 peer；论坛还必须核对完整话题名和真实话题 ID。
论坛选择只在目标群的话题列表中查找，按精确 ID 点击对应行，页面就绪立即继续，
无需固定等待或按屏幕坐标猜测位置。遇到同名歧义、话题缺失或 ID 不一致会停止发送。
在 GUI 添加会话时，论坛群会显示话题列表，必须选择发送位置。普通群和私聊不需要选择；切换到另一个群会清除旧话题。读取列表和话题只做导航，不会改写 Telegram 输入框。识别结果按账号和群缓存 5 分钟，也可手动刷新。

新选择保存 `is_forum: true`、`topic`（完整名称）和 `topic_id`（正整数字符串）。同名话题在选择器中显示不同 ID；发送时同时核对名称与 ID。话题被删除或改名时停止发送，请重新选择。

旧版仅有 `topic` / `folder` 的配置继续兼容。其已验证 ID 保存在账号 profile 的 `checkin-topics.json` 中，缓存失效会根据当前列表重新解析；存在同名歧义则停止。显式配置的 `topic_id` 不会自动替换成另一个同名话题。

Telegram 输入框有原草稿时，固定先暂存并清空草稿，执行该会话的签到动作，最后恢复到原群/话题输入框，交由 Telegram 自动保存。
发送失败或取消也会恢复。暂存前先写入账号 profile 的 `checkin-drafts/` 备份；恢复成功后删除该备份。
如果会话已改变、用户新输入了其他内容或富文本恢复不完整，会保留备份并在详情和日志中提示，避免覆盖新草稿。
发送文字、提交图片或点击按钮前再次核对，失败时立即停止并记录「未发送」。

`@用户名` 必须能从实际匹配的搜索结果解析出 peer；无法可靠解析时会停止，
请从会话列表改选数字 ID。不要用相似群名猜测实际目标。

### 反馈归属

采集以**消息 ID + 发送时间边界**为基础，使用 MutationObserver 保留短暂出现后被删除的反馈。
文字相同的新消息仍可识别；旧消息、旧 outgoing ID、其他动作的回复不能替本动作确认。
支持同一条新消息被机器人编辑后更新判定；回复关联信息晚于正文出现时，也会重新核对归属。读取正文会排除表情回应、用户头像缩写及发送状态时间。

发送后最多条件等待 12 秒，跟踪临时 ID 到正式服务器 ID 的变化，不重复提交消息。只有临时 ID 或没有可靠 ID 时保留“发送待核对”；仅凭相似文字不会把无关联成功反馈改成已确认。

只读补查会按原发送时间回看历史，避免只检查最新屏幕而漏掉被虚拟列表移出的反馈。若当天记录保留了可靠发送边界，即使缺少消息 ID，也可以发起补查。恢复 ID 必须找到时间窗口内文字一致的唯一自发消息，或发送后 30 秒内明确提及当前登录账号数字 ID、且回复目标唯一的反馈；名称相同、其他账号的反馈或多个候选均不能确认。补查不会发送文字、图片或点击签到按钮。

- 群聊：仅明确回复本轮发送消息的反馈可用于确认。
- 私聊：允许使用本次发送后的对方反馈，详情标记为「私聊反馈」。
- `reply_only`：只采集关联回复。
- `after`：也留存群内其他新消息供诊断，但无归属证据的文字不算确认成功。

因此某些以前靠群内「签到成功」泛词判绿的会话，现在会显示未确认。
这是更严格的结果证据要求；仅测试话术匹配不能验证消息是不是回复给本账号。

### 五种签到方式与多步动作

| 方式 | 必要配置 |
|---|---|
| 文字签到 | 文字；多行表示每次随机选一条 |
| 口令签到 | 如 `/checkin` |
| 口令＋按钮 | 口令、按钮文字；一行一级，按顺序点击 |
| 图片＋文字 | 本地图片路径、说明文字 |
| 仅图片 | 本地图片路径 |

图片相对路径基于项目目录，如 `images/checkin.jpg`。当前仍使用本地图片路径。
添加多个动作可按顺序发送，每步有独立反馈边界与判定；必需按钮失败或发送失败会停止后续动作。
所有必需动作都确认成功，整组才成功。只找到第一步的成功回复不会掩盖第二步未确认。
口令发送回执不确定时，尚未执行完的必需按钮仍计为待确认；只读补查不会替代点击或重新发送口令。
后续动作在准备阶段失败或取消，也会保留前面动作的已发送证据和当天标记。

### 共用签到系统

同账号内为多个群填写相同的系统名，其中一个确认成功后，其他成员标为共享成功并跳过发送。
可指定主签到群。发送了但未确认时不会马上向其他成员连发；可以先补查，再决定是否重签。
共享成功与实际发送分别记录，之前尝试失败的成员也能得到正确的系统最终状态。

### 未确认、失败与取消

- **未发送失败**：导航、身份核验或其他发送前步骤失败，没有向目标发送。
- **已发未确认**：已执行发送，但没有本轮可归属的成功反馈；不等于没有发送。
- **发送后的失败**：例如必需按钮缺失，详情仍会明确说明已经发送过口令。
- 同一天已发出或发送状态不明的动作会留存标记，普通整轮执行不会盲目重复发送。
  单独重签会展示本次目标与重复发送提醒。
- 「仅补查反馈」只读原消息链，不重发。旧版记录缺少消息 ID 时不能安全自动补查，请先在 Telegram 核对。
- 继续签到的中间确认提示不按其中的“无法”“异常”等泛词判定失败；明确结果和群级自定义关键词仍优先。旧关键词误判可通过只读补查重新核对，缺失按钮等执行错误继续保留。
- 关联反馈已有明确结果但专属规则未命中时，详情会提示「判定词需要核对」。检查机器人话术是否改变，保留或调整对应规则后仅补查反馈；提示不会自动替换规则或修改结果。按钮未完成、缺少消息 ID 会分别提示。
- 取消任务停止后续动作并清理浏览器；已经发送出去的消息不会撤回。

## 配置与数据

复制 `config.example.yaml` 为 `config.yaml`，也可直接使用工作台创建配置。

| 文件 / 目录 | 用途 |
|---|---|
| `config.yaml` | 账号、会话、动作与全局设置；保存前自动备份 |
| `data/web_profiles/` | 各账号浏览器登录资料；不要公开或手动混用 |
| `data/locks/` | 跨进程任务和账号锁；进程退出自动释放，不会强杀其他浏览器 |
| `state.json` / `.bak` | 当日发送标记、完整结果和可补查的消息证据 |
| `history/年-月.csv` | 执行记录；原有 CSV 格式保留 |
| `logs/capture-*.json` | 本轮结果及原始反馈、动作证据；含本地私密资料 |
| `logs/checkin.log` | 运行日志，5 MB 轮转，保留 3 个备份 |
| `data/schedule-state.json` | 每日计划的持久化触发记录，防止重启重复触发 |
| `data/secrets.json` | Server酱私密密钥，不回显、不导出、不发布 |
| `data/notification-status.json` | 最近一次推送结果，不含密钥 |

配置和状态使用临时文件 + 原子替换，避免读取到半个文件。状态损坏会尝试有效备份，
无法恢复则停止执行，不会把已签标记直接当成空状态。不要靠删除状态文件强制重签。
账号改名迁移 profile、标记、当日状态和会话缓存；删除账号前应保存其他草稿，删除会话失败会明确报错。
账号名不允许点目录、Windows 保留名或内部状态保留前缀，大小写冲突也会被拒绝。

### 全局选项

- `group_delay_seconds`：同一账号连续发送的最小间隔基准，数字或 `[最小, 最大]`，默认 `[1, 3]`。会话结束后立即导航到下一目标，同步最新消息后只等待尚未用完的间隔。
- `account_delay_seconds`：数字或范围，默认 `[0, 0]`；第二个账号启动前开始错峰。
- `reply_wait_seconds`：从实际发送后计算反馈观察上限，默认 6 秒；收到可判定的可信结果后静默 2 秒可提前结束。处理中或待确认提示会继续观察到配置上限，不额外延长时限。
- `reply_second_pass`：是否在本轮后补查未确认项；不会重新发送。
- `web_proxy`：留空探测系统代理和常见本地端口，也可指定 `http://127.0.0.1:7890`。
- `web_headless`：命令行默认是否后台运行；控制台手动签到在发送预览中独立选择“显示签到过程”，默认显示。体检与补查默认也显示浏览器，扫码始终显示。读取会话列表使用后台浏览器。
- `web_browser_channel`：可选 `chrome` 或 `msedge`，使用已安装浏览器；默认 Playwright Chromium。
- `gui_host` / `gui_port`：默认 `127.0.0.1:8577`。
- `gui_token`：可选访问令牌；前端所有 API、删除操作和下载均携带 `X-Token`。
- `schedule`：`enabled`、`time`、`timezone`、`headless`、`catch_up` 和 `accounts`；空账号数组表示全部。
- `notifications`：`enabled`、`only_on_issues`；SendKey 单独保存或由环境变量提供。
- 云端环境变量：`CHECKIN_GUI_HOST`、`CHECKIN_GUI_PORT`、`CHECKIN_GUI_TOKEN` 可覆盖配置；非本机监听必须设置令牌。

全局和群级成功 / 失败词是数组，一行一条。支持 `第 X 位签到` 或 `第 {n} 位签到`，
数字和相邻空格可变化。判定优先级：群级成功 → 群级失败 → 全局失败 → 全局成功。
各账号显式配置的词不会再被另一个账号静默覆盖，需要继承时由编辑器明确执行。
